# 必赢 · 标讯雷达 —— 资质匹配细则（给 Agent 执行）

> 由 SKILL.md「五、资质匹配」引用。命令里的 `<PY> <RADAR>` 同 SKILL.md「〇」。

资质档案只保存在**用户本机** `~/.bidwin/profile.json`，由 `radar.py profile` 命令读写。**不得写进平台的记忆 / 笔记。**

档案分三块，来源不同：

| 内容 | 怎么来的 |
|---|---|
| 成立时间 / 注册资本 / 参保人数 / 注册地 | 安装时的问卷（可跳过）；档案里已有其它项、只缺这一项时，看标遇到了再问 |
| 资质证书（有 / 没有） | **不设问卷**。看标时遇到公告要求、档案里又没记过，再问一句 |
| 业绩案例（有 / 没有） | 同上 |

> **档案完全为空（用户跳过了问卷）时，以上都不问，详情也不展示对照。** 只在查标结果那条回复的最后提示一次（SKILL.md「三、第六步」），等用户主动说「填写我的资质」。

「没有」也要记：记住没有，下次遇到才能判得准。

## 比对结果怎么读

detail 输出里的 `match`、screen 输出里每一条，结构相同：

| 字段 | 含义 | 你怎么用 |
|---|---|---|
| `match_line` | 脚本写好的成品结论句 | **原样抄**，不改写、不翻译、不自己总结 checks |
| `fold` | 有确定不符合的门槛 | 推送时决定是否折叠（见 SKILL.md「六、每日推送」） |
| `cert_clauses` | 公告里档案没记过的资质要求原文 | 见下「资质证书」 |
| `case_gate_clauses` | 业绩**门槛**原文（不满足就不能投） | 见下「业绩」 |
| `case_score_clauses` | 业绩**评分项**原文（只影响得分） | 见下「业绩」 |
| `asks` / `ask_next` | 脚本建议问的基本门槛问题 | 见下「按需追问」 |

> ⚠️ 「未提及」= 脚本查过了、公告没写这项，**不是**「没核对」。

> ⚠️ 比对只覆盖**公告正文**。很多公告把完整的资格条件放在附件招标文件里，正文只有一句「详见招标文件」。所以在看详情时，`match_line` 为 ✅ 且 `附件数` > 0 的，在对照结果后加一句：「以上依据公告正文，完整资格条件以招标文件为准。」

**资质证书**：读 `cert_clauses`，提炼出要求的证书名（如「ISO9001 质量管理体系认证」），对照 `known_certs`：
- 已记过 → 已由脚本判好，不用再说
- 没记过 → 写一行「⚠️ 还要求《XX》」，问题放到回复末尾统一问（算一次追问）
- 看不出具体是什么证的套话，忽略

**业绩**：先看是门槛还是评分项，再对照 `known_cases`（语义比对，由你判断，比如「汽车品牌 TVC」能覆盖「车企 TVC」）：

| 情况 | 输出 |
|---|---|
| 门槛，档案里有对得上的「有」 | `✅ 业绩：要求<原文要点>，你们有<档案项>` |
| 门槛，档案里有对得上的「没有」 | `⚠️ 业绩门槛可能不满足：要求<原文要点>，你们之前说没有` |
| 门槛，档案里对不上 | `⚠️ 业绩门槛：要求<原文要点>`，问题放到回复末尾统一问（算一次追问） |
| 评分项 | `ℹ️ 业绩为评分项：<原文要点>`（不追问） |

- 业绩和「对不上名字的证书」**永远不影响 `fold`**：语义判断会有误差，不能因此让用户看不见一条标
- 只有脚本判定的 `fold` 才折叠

## 按需追问

- **一次回复里最多问 2 个问题**，**只在回复最后集中问一次**，条目下面只陈述要求、不带问句；用户只需回「有 / 没有」或一个数字
- 优先级：`ask_next`（脚本按出现次数排好了）> 证书 > 业绩
- 同一轮对话里用户没回答的问题，不要重复问
- `ask_enabled` 为 false（用户说过「别问了」）→ **一律不追问**，只标注
- 用户回答后**立刻**存档，然后简短确认：「记下了，以后遇到同类要求会自动判断。」

| 用户回答 | 命令 |
|---|---|
| 注册资本 / 成立时间 / 参保人数 / 注册地 | `<PY> <RADAR> profile set --capital-wan 500`（对应 `--established` / `--headcount` / `--reg-area`） |
| 证书有 / 没有 | `<PY> <RADAR> profile cert --name "ISO9001质量管理体系认证" --has yes`（或 `no`） |
| 业绩有 / 没有 | `<PY> <RADAR> profile case --name "汽车品牌TVC" --has yes`（或 `no`） |

业绩的 `--name` 写成**可复用的类型**（行业 + 类型，如「汽车品牌TVC」「政府宣传片」），不要写成某个具体项目名。

## 列表精筛（用户说「按资质筛一下」，或同意了列表结尾的提议）

```
<PY> <RADAR> screen --ids "<id>|<publish_time>;;<id>|<publish_time>"
```

- 传入**当前已展示**的那批（按展示顺序），一次最多 30 条
- 输出：先列未截止、门槛无异常 / 需确认的（沿用原编号，每条下面加一行 `match_line`），再用一行汇总折叠掉的：「另有 N 条门槛不符已折叠（注册资本不足 2 条、要求本地注册 1 条），回复『看折叠的』展开。」
- `expired` 为 true（已过报名截止）的也折叠，单独一行：「另有 N 条已过报名截止，已折叠。」
- `push_mode` 为 `all` 时不折叠，门槛不符的排在最后，照常标注
- screen 顺带拿到了 `signup_deadline` / `countdown`，可以在每条后面附上报名截止
- 用户回「看折叠的」→ 从已拿到的 screen 结果里列出被折叠的那几条（编号接着往下排），每条附 `match_line`，**不重新请求**

## 管理档案

| 用户说 | 命令 |
|---|---|
| 「看看我的资质档案」 | `<PY> <RADAR> profile show`，用人话列出来 |
| 「填写我的资质」 | 照 SKILL.md「资质问卷」问 4 项 |
| 「我们拿到 XX 证了」「注册资本改成 1000 万」 | 对应的 `profile cert` / `profile set` |
| 「XX 那条记错了」 | `profile cert --name "XX" --remove`（业绩用 `profile case`） |
| 「别再问我资质了」 | `profile set --ask off`；「可以继续问」→ `--ask on` |
| 「推送里不符合的也给我看」 | `profile set --push-mode all`；改回 → `--push-mode fold` |
