# 必赢 · 标讯雷达 —— 定时推送（给 Agent 执行）

> 由 SKILL.md 开头「先看这里」和「六、定时推送」引用。命令里的 `<PY> <RADAR>` 同 SKILL.md「〇」。
> **凡是和「每天 / 定时 / 推送 / 盯着 / 定期看看」有关的，都按本文逐步执行，不要按自己的理解另起一套。**

推送条件只保存在**用户本机** `~/.bidwin/watch.json`，由 `radar.py watch` 命令读写。
**不得把推送条件写进平台的记忆 / 笔记**——换平台、换对话都会丢，也会被改乱；以这个文件为唯一依据。

---

## 〇、为什么必须走这里

定时推送只查**近 3 天**，**以前推送过的标自动跳过**，每天只花几次到几十次请求。
如果每天把「近一个月」重新搜一遍、再对几百条逐条查截止，一天就是几百次请求，看到的还大多是昨天看过的。实测有用户自己建了定时任务、内容写成「帮我查一下 XX 的标」，就是这样。

所以：

1. **定时任务的内容只能是固定的一句**：「**用标讯雷达推送今天的新标**」。不写别的、不加条件——条件在 `watch.json` 里。
2. **定时任务触发时只执行 `watch run`**（见下文「二、执行推送」），**不得**改成 `search --last 1m` 之类的全量搜索。
3. 当前对话是**定时任务自动发起的**（不是用户实时在问），但内容不是上面那句、而是让你查某类标：
   - `watch list` 里已有推送条件 → 照「二、执行推送」执行 `watch run`，结尾加一句：「这个定时任务的内容建议改成『用标讯雷达推送今天的新标』，以后每天只推送新发布的标讯，不会重复出现看过的内容。要我帮你改吗？」
   - 还没有推送条件 → 按任务内容正常查一次标（`--days 3`），结尾问：「要把这个条件设成定时推送吗？以后每天只推送新发布的标讯，不用每天重新查一遍，也不会重复看到之前的内容。」用户同意 → 「一、设置」
4. 搜索输出里出现 `repeat_hint`（同样的条件前几天已经全量搜过）→ 在回复末尾建议用户设成定时推送，用户同意 → 「一、设置」。

## 一、设置（用户说「每天帮我推送…」「帮我盯着…」，或同意了查标结尾 / 安装结尾的提议）

### 第一步：定条件

- 刚查过标 → 沿用这次的检索条件（主题词 / 必含 / 排除 / 地区 / 金额 / 采购类型），不必再问。**但这次的主题词如果明显属于不同业务**（如「展会、活动策划、发布会」和「宣传片、短视频、视频拍摄」），先按下面「按业务分组」拆成几组：主题词按业务分开，地区 / 排除词 / 金额 / 采购类型等其它条件每组都沿用。两条规则冲突时，**按业务分组优先**——混在一组里，一类业务的拆字噪音会带进另一类的推送
- 用户直接要求推送 → 只问缺的几项，**一次问完**：想盯什么方向？哪些地区（不限就是全国）？有没有不要的类型？金额下限？
- **推送时间由用户定**：用户没说几点的，和上面缺的几项一起问一句「每天几点推送给你？」。用户说随便 / 没回答时间 → 用 09:00，并告诉用户随时可以改
- 按 SKILL.md「三、第一步」的要点把人话拆成参数
- **不问称呼、公司、职位等与检索无关的信息**

**按业务分组：方向很宽时，收进最多 3 组，不按单个词拆。**

- 每组是一类业务，用 `|` 放 5~10 个**招标公告里常见的叫法**；同一类的说法都放进同一组
- 业务实在太多、3 组装不下时，把**最接近的两类**并成一组（如「宣传片」和「专题片拍摄」），不要把差得远的硬塞在一起（如「宣传片」和「医院宣传品」）；并完试查噪音大，就和用户商量去掉哪一类
- 例：用户说「汽车营销相关的都要：公关、品牌、新媒体、抖音小红书、海外传播」→
  - 「汽车公关传播」：`汽车公关|车企公关|汽车品牌传播|汽车公关传播|汽车品牌推广`
  - 「汽车新媒体」：`汽车新媒体|汽车社交媒体|汽车KOL|汽车达人|汽车短视频|汽车直播`
  - 「汽车海外传播」：`汽车海外传播|汽车出海营销|车企海外传播|汽车海外营销`
- ❌ 不要把「公关」「品牌」「抖音」「小红书」各设一组，也不要用这类单独的泛词：一个月几万到几十万条，第一页只能看到最新几小时，大多是套话

### 第二步：试查一次

用近 3 天试查，确认条件靠谱：

```
<PY> <RADAR> search <条件> --days 3
```

- `total` 为 0 → 按 SKILL.md「三、第四步」的「没找到」处理，和用户换个叫法
- 按 SKILL.md「三、第三步」筛一遍，再按「三、第四步」看量和噪音：
  - 留下的很少（噪音大）→ 先和用户换说法，再保存
  - `coverage.complete` 为 false（近 3 天的新标一页都装不下）→ 告诉用户每天会漏一部分，从「限定地区 / 设金额下限 / 只看服务类」里挑这组还没用上的建议收窄；用户说不用 → 照原条件保存
- 多组时逐组试查（每组一次）

### 第三步：保存

给这组条件起个短名字，如「北京数字人」：

```
<PY> <RADAR> watch set --name "北京数字人" --keyword "数字人|虚拟人" --exclude "数字人民币" --area 北京
```

- **保存的条件要和试查时完全一致**（主题词、排除词、地区等一个都不改）。想改哪一项，就用改后的条件再试查一次，确认没问题再保存
- 最多保存 3 组；同名会覆盖（即修改）
- 已有 3 组、用户还要加 → 先看能不能并进已有的某一组（同一类业务就用 `|` 合进去），不能再问用户替换哪一组
- 「组」「3 组上限」是内部概念，**对用户不说「组」**：说「推送方向」或直接说组名
- **能合并就直接合并，不向用户提上限**：说「我把这几个方向整理成两个推送方向：……」，不说「最多只能设 3 个所以……」。只有合并不了、要用户取舍时，才说明上限，例如「推送方向最多同时 3 个，现在有汽车公关、汽车新媒体、汽车活动，新加的『展会搭建』要替换掉其中哪一个？」
- 保存后用人话回述：「已保存推送条件『北京数字人』：主题 数字人 / 虚拟人，北京，排除 数字人民币。」

### 第四步：建定时任务

- 你所在的平台**支持由你直接创建定时任务** → 征得用户同意后创建：每天在**用户定的时间**运行，任务内容固定为「**用标讯雷达推送今天的新标**」
- 不支持 → 把步骤告诉用户：在 AI 助手里新建一个每天 <用户定的时间> 运行的定时任务，任务内容填「用标讯雷达推送今天的新标」（**一字不改**）
- 已经有内容为这句话的定时任务 → 不要再建第二个；加一组条件不需要新的定时任务

所有组都保存好、定时任务也建好（或已告诉用户怎么建）之后，最后告诉用户：「设置好了，从明天 <用户定的时间> 开始推送。想改条件、改时间、加一组或取消，直接跟我说。」
还有组在等用户确认（如试查噪音大、正在商量换词）时，**先不说「设置好了」**，只说已保存了哪几组、哪一组还等用户回复。

## 二、执行推送（定时任务触发「用标讯雷达推送今天的新标」，或用户手动说同样的话）

```
<PY> <RADAR> watch run
```

- 查近 3 天，**以前推送过的标自动跳过**，只返回新标
- 按各组的 `results` 做 SKILL.md「三、第三步」的相关性筛选排序
- **查截止 + 资质精筛（必做）**：列表里没有报名截止日期，所以**不管用户有没有填资质**，都要把各组筛完后保留的标的 id **合并成一次** `screen --ids "<id>,<id>,…"` 调用（超过 30 条就分两次），然后：
  - **`expired` 为 true（已过报名截止）的直接不推送**，也不在回复里提
  - `screen.match_enabled` 为 true（填过资质）时，其余的再按资质处理（先读 `references/matching.md`）：
    - `push_mode` 为 `fold`（默认）：`fold` 为 true 的不展示，每组末尾一行汇总：「另有 N 条门槛不符已折叠（<原因归类计数>），回复『看折叠的』展开。」
    - `push_mode` 为 `all`：全部展示，门槛不符的排在组内最后
    - 每条展示的标下面加一行 `match_line`
  - `screen.match_enabled` 为 false（没填资质）：不做资质处理；有 `profile_hint` 就在结尾原样说一次
  - 每条展示的标都附上报名截止与倒计时（screen 已经拿到了）
- **只对筛完保留的标做 screen**，不对各组的全部原始结果做
- **按组输出**，每组一个小标题（组名）；编号**全部连续**（第二组接着第一组往下排），格式同 SKILL.md「三、第五步」，每组最多 20 条
- 某组有 `coverage_warning`（近 3 天的新标一页装不下）→ 在该组末尾加一句：「这组条件新标较多，每天会漏掉一部分，建议加地区或金额收窄，跟我说一声就能改。」
- 首句：「按 `date_range` 检索，今天有 N 条新标：」（N = 展示的条数，不含折叠的）
- 全部都没有新标，或新标全都已过报名截止 → 只回一句：「今天暂无新标。」全被资质折叠 → 「今天有 N 条新标，但门槛都不符，已折叠，回复『看折叠的』查看。」
- 结尾：「回复编号看详情；想改推送条件随时说。」有追问的放在最后（见 `references/matching.md`「按需追问」，最多 2 个）

## 三、修改 / 查看 / 取消

| 用户说 | 命令 |
|---|---|
| 「我现在推送的是什么」 | `<PY> <RADAR> watch list`，用人话列出各组 |
| 改条件（如「推送再加上天津」） | 用**同名** `watch set` 覆盖，参数写完整 |
| 「再帮我盯一下 XX」 | 按「一、设置」，能并进已有的组就并进去 |
| 「不要推 XX 了」 | `<PY> <RADAR> watch delete --name "XX"` |
| 「全部停掉」 | 逐个 delete，并提醒用户把定时任务也关掉（你能直接关就征得同意后关） |
| 「推送时间改成 8 点」「改到下午 2 点」 | 改定时任务的时间（你能改就征得同意后改；不能就告诉用户去定时任务里改），内容仍是那句固定的话，不另建任务 |
